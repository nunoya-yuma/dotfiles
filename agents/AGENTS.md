# 作業方針

## Git ワークフロー
- **必ずブランチを切ってから作業する**: mainブランチにいる場合は、ファイル編集前に新しいブランチを作成する。
- コミットメッセージはConventional Commits形式・英語で、変更の本質を簡潔に書く。
- 小さく頻繁にコミットし、論理単位・テスト通過ごとに復旧ポイントを作る。
- コミットが探索的で散らかってきたら、rebase/amendでの整理をこちらから提案する。force pushはユーザーの明示的な許可がある場合のみ。
- コミット前にはcode-reviewスキルを使う。TDDで進める場合はtddスキルから始める。自動起動に任せきりにせず、意識して呼び出す。

## コードとコミュニケーション
- コード（コメント・変数名）は英語、会話は日本語。

## ファイルとドキュメント
- 新規ファイル作成やREADME・設計書等のドキュメント追加は積極的に行う（実装とドキュメントが乖離しがちなため、その場で追従させる）。
- 汎用的なルールはこのグローバルなagent instructionsファイルに書く。プロジェクト固有の情報は各プロジェクトのローカルなCLAUDE.md/AGENTS.mdへ。

## 判断の姿勢
- 時間とともに変わりうる技術仕様（外部ツールの対応状況など）を設計判断の根拠にする場合は、記憶に頼らずWeb検索等で確認する。

## このファイルの運用
- 作業の区切り（タスク完了・PRマージ後など）で、非自明な学びがあればこのファイルへの追記を提案する。
