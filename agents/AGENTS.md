# CRITICAL: 作業開始前に必ず確認

- **作業ブランチ**: mainブランチで作業する場合は、**最初に新しいブランチを作成してから**作業を開始すること。ファイル編集やコード変更の前にブランチを切り替える。作業が完了したらGitHubでPRを作成してマージする。

- コミットメッセージに関しての注意:
  - Conventional Commitsの形式に従う（例: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`等）
  - メッセージは英語で記述する
  - 簡潔で明確、かつ変更の本質を説明するものであるべき
  - 具体的な変更点、修正理由、影響範囲などを簡潔に記述する

- 言語設定: コードのコメントや変数名は英語を基本とする。会話は日本語で、コード内は英語を優先する。

- ファイル作成方針: 新規ファイル作成は積極的に行って良い。ドキュメントファイル（README、設計書等）の作成も積極的に提案する。

- テストとリント: コード変更後は必ずテストの実行とリントチェックを行う。失敗した場合は修正してから次の作業に進む。特にruff、pytest等のプロジェクト固有のコマンドはCLAUDE.mdに記載されたものを使用する。

- 作業進捗の管理: 複雑なタスクや複数ステップの作業では必ずTodoリストを使用して進捗を管理し、ユーザーに可視化する。各タスク完了時に即座にステータスを更新する。

- セキュリティ: APIキーやトークンなどの機密情報はコードやコミットに含めない。環境変数や設定ファイルを適切に使用する。

- コミット戦略: 小さく頻繁にコミットする。1つのruffルール修正、1つの機能変更、設定変更等の論理単位で即座にコミット。各コミットは独立して動作する状態を保つ。テスト通過やビルド成功の節目で必ずコミットして復旧ポイントを作る。複雑なタスクでも細かい段階に分割し、作業の進捗を保存する。

- 設定ファイルの使い分け: プロジェクト固有でない一般的なルールや方針はグローバルCLAUDE.md（~/.claude/CLAUDE.md）に保存する。プロジェクト固有の技術情報のみローカルCLAUDE.mdに記載する。
