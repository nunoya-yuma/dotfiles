# TDD: Refactor

前提: 全テストがGreenの状態であること。Greenでない場合は先に `/tdd-green` を完了させてから呼び出すようユーザーに伝える。

## やること

1. Tidy First原則に従い、構造変更のみを行う。振る舞いやテストの期待値は変更しない。
2. 変更ごとにテストを実行し、Greenを維持していることを確認する。
3. 作業中に振る舞い変更(新機能・バグ修正)をしたくなった場合は、その場でやらず提案に留めてユーザーに確認する。
4. 変更内容の要約をユーザーに提示し、ここで停止する。

## 禁止事項

- 振る舞いを変える変更(新機能・バグ修正)を紛れ込ませること
- テストの期待値やアサーションを変更すること
- 次のテストケース(次のRed)へ自動的に進むこと。ユーザーが `/tdd-red` を呼ぶまで待つ
