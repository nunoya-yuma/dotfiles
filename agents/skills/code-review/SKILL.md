# Code Review

## Overview

- ユーザに指定されたファイルもしくはgitのコミット前のファイルに対して、コードレビューを実施してください。
- 良い実装についてもコメントをしてください。
- コードレビューは日本語で実施してください。

## 観点

- シンボル名はわかりやすいか
- コードベースのほかの場所と共通化できないか
- ログ出力に過不足はないか
- セキュリティ上問題ないか
- 関数や変数のスコープや可視性は適切か
- publicなAPIにはコメントがついているか、最新のコードと乖離がないか
- 一画面に収まらないほど関数が大きすぎないか
- forやifなどが重なり、処理が複雑すぎないか
- 根本的な改善点はないか
- 過剰になっていないか。追加した各要素(型・関数・引数・設定項目・分岐・例外処理)について「消したら何が壊れるか」を具体的な呼び出し元や要件で答えられるか。「将来必要になるかも」「念のため」は理由として認めない。典型例は以下
  - 実装が1つしかないinterface、呼び出し元が1箇所の薄いラッパー
  - 使われていない引数・オプション・設定項目
  - 起こりえない状態への防御コード、複数層で重複したバリデーション
  - 要件に含まれない「ついで」の変更

他人のPRをレビューする場合は`pr-review`を使う。
