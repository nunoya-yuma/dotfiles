# Reflect

## Overview

- このセッションでの会話・作業（ユーザーからの修正指示、確認済みの非自明な判断、再利用できそうな知見）を振り返り、CLAUDE.md/AGENTS.mdや既存skillへの反映が必要か判断してください。
- 反映が不要と判断した場合はその旨を一言伝えるだけでよく、無理に何かを書き足さないでください。
- ファイルへの書き込みは、内容と反映先を提示してユーザーの承認を得てから行ってください。
- Claude Codeのauto memory（セッションを跨いで自動保存される個人向けメモリ）とは役割が異なる。auto memoryは非公開でツール固有だが、このスキルが扱うのはCLAUDE.md/AGENTS.md/skillという、人間が読み他ツール（Codex/Copilot等）からも参照される恒久的な文書。両方に同じ内容を書く必要はなく、恒久的な指示・知見として残すべきものだけをここで扱う。

## 学びの判定基準

- ユーザーから明示的な修正・訂正を受けた、または非自明なアプローチを（黙示的にではなく）確認・承認された内容か
- 今後の別セッション・別プロジェクトでも再現性のある知見か（一度きりの作業詳細やタスクの進捗は対象外）
- 既存のCLAUDE.md/AGENTS.md/skillに未反映か（該当ファイルをgrep等で確認し、重複や矛盾がないか確かめる）
- 時間とともに変わりうる外部仕様そのものの丸暗記ではないか（そうした内容は書き込まず、都度確認する方針自体を書く）

## 反映先の判断

- プロジェクト固有の知見 → カレントプロジェクトのローカルCLAUDE.md/AGENTS.md（存在しなければ新規作成してよい）
- プロジェクトを問わない汎用的なワークフロー・好み → グローバルのCLAUDE.md/AGENTS.md
- 特定skillの使い方・判断基準に関する知見 → 該当skillのSKILL.md

## 進め方

1. このセッションの会話と、コミット前提のdiffを振り返り、学び候補をリストアップする
2. 各候補について反映先（上記）と具体的な追記・修正文言を提案する
3. ユーザーの承認を得てから該当ファイルを編集する
4. 反映後、どこに何を書いたかを簡潔に報告する
