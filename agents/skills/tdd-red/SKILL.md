# TDD: Red

前提: `tdd` skillで作成されたテストリストが会話中に存在すること。存在しない場合はユーザーに確認してから進める。

## やること

1. テストリストから未着手の項目を **1つだけ** 選ぶ。どれを選ぶかユーザーと合意がなければ確認する。会話中に新しいケースが見つかっていた場合は、先にテストリストへ追記してから選ぶ。
2. そのテストケース1つだけを実装する。既存のテストコードやテストリストの他の項目には触れない。
   - テストが呼び出す関数・クラスがまだ存在せず、テストコードを完成させるのに何行も必要になる場合は、
     一度に書ききらない。1行(またはひとまとまりの最小の追加)を書いて実行し、出たエラー
     (`ImportError`、`AttributeError`など)を確認する、という1サイクルを実行したら、**そこで応答を
     終了してユーザーに確認を求める**。同一ターン内で複数行分をまとめて追加したり、複数サイクルを
     連続実行したりしない。ユーザーから続行の意思(「次へ」「OK」など)が示された新しいメッセージが
     来てから次の1行に進む。
3. テストが完成し実行できる状態になったら、想定通りの理由でRedになることを確認する(構文エラーや無関係な失敗でRedになっていないか確認する)。
4. プロダクションコードは一切変更しない。
5. 積み重ねた差分をまとめたdiffとテスト失敗の出力をユーザーに提示し、ここで停止する。

## 禁止事項

- 複数のテストケースを同時に追加すること
- プロダクションコードを変更すること(インターフェースのガワ作りも含め、ユーザーからの明示的な依頼がない限り行わない)
- テストコードを組み立てる途中の1サイクル(1行追加 → 実行 → エラー確認)を終えるごとにユーザーの確認を
  挟まず、複数サイクルを同一ターン内で連続実行すること
- 最初からGreenになってしまうテストを書くこと
- Greenフェーズの作業を先取りすること。`/tdd-green` をユーザーが呼ぶまで待つ
